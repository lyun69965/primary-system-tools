## 实例 1：前后台初体验（虚拟机）

🎯 **练什么**：后台启动、查看、拉回、挂起、恢复
📝 **任务**：启动 `sleep 100`，让它前后台来回切换一圈，最后结束它。

💡 **思路**：
1. 命令后面加什么符号 = 后台启动？（`&`）
2. 看后台任务用什么？（`jobs`）
3. 拉回前台？挂起？恢复？

🔧 **参考**：
```bash
sleep 100 &        # & 让它在后台跑，终端显示 [1] 12345
jobs               # [1]+  Running  sleep 100 &
fg %1              # 拉回前台（开始等 100 秒）
# 按 Ctrl+Z 挂起 → [1]+  Stopped
bg %1              # 再放回后台继续
jobs               # 又是 Running
kill %1            # 结束它（%1 用任务号代替 PID）
```

✅ **自查**：jobs 能看到任务状态 Running/Stopped 变化；最后 jobs 变空（任务结束）。

## 实例 2：输出与错误分开（虚拟机或 git-bash）

🎯 **练什么**：`>` 和 `2>` 把正常输出、错误输出分开记录
📝 **任务**：写一个同时输出"正常信息"和"错误信息"的小命令，让它们分别落到两个文件。

💡 **思路**：
1. 正常输出走 `>`，错误输出走 `2>`
2. 怎么让一条命令既输出正常又输出错误？（`echo x` 是正常，`echo y >&2` 是错误）

🔧 **参考**：
```bash
(echo "这是正常输出"; echo "这是错误输出" >&2) > out.log 2> err.log
# 解释：小括号把两条 echo 合成一组；>&2 让第二条走标准错误
cat out.log   # 只有"这是正常输出"
cat err.log   # 只有"这是错误输出"
```

✅ **自查**：两个文件内容各自独立，正常/错误分得清清楚楚。

## 实例 3：trap 捕获信号（虚拟机）

🎯 **练什么**：trap 机制 + kill -TERM 与 kill -9 的区别
📝 **任务**：写脚本 trap 捕获 TERM，打印"清理中"再退出；分别用 `kill -TERM` 和 `kill -9` 测试。

💡 **思路**：
1. trap 语法：`trap '要执行的命令' 信号`
2. TERM 能被捕获、KILL 不能被捕获——这是核心区别

🔧 **参考**：
```bash
cat > t.sh <<'EOF'
#!/bin/bash
trap 'echo 清理中; exit 0' TERM
while true; do echo 运行中; sleep 1; done
EOF
chmod +x t.sh

./t.sh &
kill -TERM $(jobs -p)   # 终端出现"清理中"，进程退出

./t.sh &
kill -9 $(jobs -p)      # 直接被杀，没有"清理中"
```

✅ **自查**：TERM 触发 trap 打印"清理中"；`-9` 无任何输出（trap 没机会执行）。

## 实例 5：F2 语义重命名（本地 VS Code）

🎯 **练什么**：语义重命名（改符号不是改文字）
📝 **任务**：把实例4的 `add` 用 F2 改成 `my_add`，观察所有引用同步变。

💡 **思路**：
1. 光标放 `add` → F2 → 输入 `my_add` → 回车
2. 对比"注释里恰好也有 add 字样"的情况——注释文字不会被改

🔧 **参考**：
```python
# utils.py
def add(a, b):        # 在这按 F2 改名
    """add 两个数"""   # 这行注释里的 add 不会被改
    return a + b

# main.py
from utils import add   # 这里的 add 会同步变成 my_add
print(add(1, 2))
```

✅ **自查**：def 和调用处都变成 `my_add`，但 docstring 注释里的 `add` 保持原样。

## 实例 7：pdb 入门（本地）

🎯 **练什么**：pdb 断点、单步、打印变量
📝 **任务**：写一个求和函数（故意在循环范围写错），用 pdb 设断点观察变量，定位 bug。

💡 **思路**：
1. `python -m pdb script.py` 进入调试
2. `break 行号` 设断点、`continue` 跑到断点、`p 变量` 打印、`n` 单步、`q` 退出

🔧 **参考**：
```python
# sumbug.py
def total(n):
    s = 0
    for i in range(n):    # 想求和 1..n，范围写成了 0..n-1
        s += i
    return s
print(total(5))           # 期望 15，实际 10
```
```bash
python -m pdb sumbug.py
# (Pdb) break 4            ← for 循环那行
# (Pdb) continue
# (Pdb) p i                ← 看 i 从 0 开始，少了 5
# (Pdb) p s
# (Pdb) q
```

✅ **自查**：能说出 bug 原因（range(n) 应为 range(1, n+1)），并用 pdb 观察到了。

## 实例 8：递归与归并理解（本地）

🎯 **练什么**：递归过程可视化
📝 **任务**：写递归阶乘，函数开头 `print(f"fact({n}) 被调用")`，观察递归"先深入再返回"的顺序。

💡 **思路**：
1. 递归 = 函数自己调自己，必须有终止条件
2. print 在 return 前 = 先看到"深入"，return 后才"返回"

🔧 **参考**：
```python
def fact(n):
    print(f"fact({n}) 被调用")
    if n <= 1:
        return 1
    r = n * fact(n - 1)
    print(f"fact({n}) 返回 {r}")
    return r
print(fact(4))
```

✅ **自查**：输出显示 4→3→2→1 依次"被调用"，再 1→2→3→4 依次"返回"——这就是递归的两阶段。

## 实例 9：调试一个排序 bug（本地）

🎯 **练什么**：综合调试 + 写回归测试
📝 **任务**：下面的冒泡排序有 bug（内层比较范围错），用调试器定位修复，写 pytest 锁死。

💡 **思路**：
1. 先运行看输出（比如结果不对/越界）
2. 断点看内层循环的 j 范围
3. 最小修复 + 测试

🔧 **参考**：
```python
# bubble_bug.py
def bubble(a):
    n = len(a)
    for i in range(n):
        for j in range(n - i):      # bug：应为 n-i-1，否则 j+1 越界
            if a[j] > a[j+1]:
                a[j], a[j+1] = a[j+1], a[j]
    return a
print(bubble([3, 1, 2]))
```
```bash
python bubble_bug.py   # IndexError: list index out of range
```
修复：`range(n - i - 1)`；测试：
```python
from bubble_bug import bubble
def test_bubble():
    assert bubble([3,1,2]) == [1,2,3]
```

✅ **自查**：修复后不越界、结果正确、测试通过。

## 实例 10：time 计时对比（本地 Git Bash）

🎯 **练什么**：用 time 测两个实现的耗时差
📝 **任务**：写"字符串拼接"慢版和"列表 join"快版，各拼接 100000 次，用 time 对比。

💡 **思路**：
1. `s = s + str(i)` 每次都新建字符串 = O(n²)
2. `''.join([...])` = O(n)
3. 在 **Git Bash** 里 `time python 文件.py`

🔧 **参考**：
```python
# slow.py
s = ""
for i in range(100000):
    s = s + str(i)

# fast.py
s = "".join(str(i) for i in range(100000))
```
```bash
time python slow.py
time python fast.py
```

✅ **自查**：slow 明显更慢（可能差几十倍）；确认自己是在 Git Bash 里跑（提示符有 MINGW64）。

## 实例 11：cProfile 找热点（本地）

🎯 **练什么**：定位"时间花在哪一行"
📝 **任务**：写递归斐波那契（故意低效），用 cProfile 找热点。

💡 **思路**：
1. `python -m cProfile -s cumulative 文件.py`
2. 输出按累计耗时排序，最上面就是热点（fib 函数被反复调用）

🔧 **参考**：
```python

def fib(n):

print(fib(30))
```
```bash
python -m cProfile -s cumulative fib.py
# 看到 fib 被调用了上百万次，累计时间最高
```

✅ **自查**：能从输出里指出"fib 函数"是热点，并理解原因（重复计算）。

## 实例 12：复杂度对比 + set 优化（本地）

🎯 **练什么**：list vs set 复杂度 + 优化不改变结果
📝 **任务**：10000 个随机数查重，先用 list 实现，再用 set 优化，对比 count 和耗时。

💡 **思路**：
1. list 版：`if x not in unique` 线性扫描 O(n²)
2. set 版：哈希 O(n)
3. count 必须一致

🔧 **参考**：
```python
# dedup_slow.py
import random
random.seed(1)
nums = [random.randint(0, 500) for _ in range(10000)]
unique = []
for x in nums:
    if x not in unique:
        unique.append(x)
print("count=", len(unique))

# dedup_fast.py
import random
random.seed(1)
nums = [random.randint(0, 500) for _ in range(10000)]
print("count=", len(set(nums)))
```
```bash
time python dedup_slow.py
time python dedup_fast.py
```

✅ **自查**：两个 count 相同；set 版明显更快。
